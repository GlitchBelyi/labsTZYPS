## 2. Очікувані питання замовника (задача 8.2)

1. **Штраф за запізнення — яке правило чинне?** SRS 1.0 суперечить сама собі: F-60 каже
   «−5 % за кожен день», BL-30 каже «−10 % за кожен день». Яке значення правильне для SRS 1.1
   і для юніт-тестів `GradeCalculator.latePenalty`?
2. **Яка спроба тесту потрапляє в журнал оцінок?** F-80 дозволяє повторне проходження тесту,
   але не вказує, яка оцінка зберігається — перша, остання чи найкраща. Це прямо впливає на
   довіру до підсумкового балу — ключову цінність продукту.
3. **Елементи оцінювання без виставленої оцінки — як рахувати підсумок?** BL-10 не визначає
   поведінку `weightedTotal`, якщо частина елементів ще не оцінена: враховувати як 0 чи
   виключати з розрахунку до появи оцінки?
4. **Зарахування з порожнім кодовим словом.** `EnrollmentValidator.canEnroll` не описує явно,
   що відбувається, якщо courses.enrolmentKey не задано (самозарахування вимкнене) чи
   користувач надсилає порожній рядок — відмова одразу чи інша поведінка?
5. **Часовий пояс дат.** Модуль використовує `java.time.LocalDate` без часового поясу (п. 2.3
   SRS). Заклади освіти можуть бути в різних часових поясах (дистанційне навчання) — чи
   достатньо дати без часу/поясу для дедлайнів і штрафів, чи це ризик для студентів з інших
   регіонів?

*Додаткові, нижчого пріоритету (якщо залишиться час на демо):* формат поділу курсу на
розділи — «тижні» чи «теми» (F-130); хто саме бачить подію курсу в календарі — лише
зараховані учасники чи всі (F-120).
