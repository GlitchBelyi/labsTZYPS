Цифри в рядках 2–5 підставляємо з фактичного прогону; до нього рядки лишаються планом.

| Час | Що показуємо | Хто | Матеріал |
|---|---|---|---|
| 0–1 хв | Контекст: продукт, модуль v1, що автоматизовано, ролі спринта | Мележик | README (розд. «Що покрито») |
| 1–3 хв | Запуск `mvn clean test` на чистому клоні, підсумок Surefire: скільки зелених, скільки червоних | Чупай | термінал, `target/surefire-reports/` |
| 3–5 хв | Один юніт-тест докладно: параметризований `latePenalty` або `ectsLetter` на межах, звідки очікуване значення (SRS 1.1, BL-30/BL-20) | Ромашко | `GradeCalculatorTest` |
| 5–7 хв | Живе виконання двох UI-сценаріїв на demo: UI-05 (негативний вхід, зелений) і UI-01 (червоний, дефект #1) | Білогривий, Чупай | `mvn test -DexcludedGroups=none -Dtest=...` |
| 7–9 хв | Дефекти модуля: 1–2 звіти в GitHub Issues (BL-80 формат результату; найсерйозніший за severity), простежуваність «BL → тест → Issue» | Александрова, Мележик | GitHub Issues, таблиця покриття |

Запасний план: якщо demo недоступне, UI-сценарії показуємо через збережені звіти Surefire й запис Selenium IDE, позначаємо їх `blocked` з причиною (каталог продуктів, 1.3), юніт-тести виконуємо наживо — вони не залежать від demo. Якщо немає інтернету, `mvn -o test` (залежності вже в `~/.m2`). Репетиція із секундоміром — обов'язково, у межах 10 хвилин.

## 2. Що має працювати до репетиції (чек-лист КТ)

- [ ] Чистий клон репозиторію, `mvn -v` показує JDK 17, `mvn clean test` дає очікуваний підсумок.
- [ ] `mvn test -DexcludedGroups=none -Dtest=LoginNegativeUiTest` проходить за < 30 с на demo.
- [ ] У Issues спринта 4 є мітка `sprint:4`, кожен звіт має Severity, Priority, версію модуля, посилання на тест і поле Reviewer.
- [ ] Таблиця «BL → тест → TC → Issue» у README збігається з тим, що запускається.
- [ ] Хто що показує і в якому порядку відкриває вікна (термінал, IDE, GitHub) відомо заздалегідь.

## 3. Питання замовнику (від КТ)

Повний перелік із обґрунтуванням — `automation-plan.md`, розд. 4. Для демо вистачає трьох:

1. **BL-80.** Формат результату `violations`: українські рядки (SRS 1.1) чи коди `KEY`, `PERIOD`, `CAPACITY`, `PREREQUISITE` (README модуля)? Від відповіді залежить, чи вважаємо розбіжність дефектом (Issue #38).
2. **BL-30 і F-60.** Підтвердіть 10 % за добу запізнення, максимум 50 %: у SRS 1.0 було 5 %, у SRS 1.1 це поки «потребує підтвердження замовником».
3. **BL-50.** Чи округлюється частковий бал питання перед підсумком (0.6667 чи 0.67)? Це змінює підсумок тесту з кількома правильними відповідями.
