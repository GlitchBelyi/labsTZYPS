# Протокол ретроспективи (Спринт 4 «Автоматизація»)

Модератор: Александрова (СМ)

## Start (почати робити)
1. Перевіряти локальну компіляцію (`mvn clean test`) перед створенням Pull Request, а не після.
2. Писати UI-тести паралельно з юніт-тестами, а не в останні дні спринту (щоб встигнути досягти нормативу).
3. Перевіряти локатори в DevTools безпосередньо перед написанням коду, щоб не витрачати час на виправлення тайм-аутів.

## Stop (припинити робити)
1. Залишати шаблонні фрази-заглушки (наприклад, «[вкажи фактичну ОС]») у звітах про дефекти (Issues).
2. Змішувати код модуля (`src/main/java`) і код тестів (`src/test/java`) в одному коміті (як це сталося з PR Чупая).
3. Забувати про обов'язкові теги `@Tag("ui")` та `@Tag("unit")` для нових тестових класів.

## Continue (продовжити робити)
1. Розділяти перевірки на «елемент є» та «текст збігається» (як у `LoginFormUiTest`), щоб один дефект локалізації не ховав результати інших перевірок.
2. Використовувати посилання на Issue (наприклад, `#35`) у `@DisplayName` червоних тестів.
3. Робити детальні описи Pull Request із зазначенням результатів локального запуску.
