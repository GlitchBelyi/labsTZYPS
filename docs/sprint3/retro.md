## Start (почати робити)
- Рецензувати кейси одразу після створення, до виконання, а не пакетом в один день.
- Перед виконанням перевіряти, що кейс має статус reviewed.
- Писати передумови так, щоб кейс створював потрібні курси, завдання й студентів сам (незалежність).
- Вести таблицю задач щодня: статус і фактичні години.
- Перевіряти статистику формулами, а не вписаними числами.

## Stop (припинити)
- Використовувати один Bug ID для різних дефектів і для кількох failed-кейсів.
- Писати кроки з кількома діями («натиснути і ввести») та очікування без перевірюваного вигляду («відкрито панель»).
- Лишати в Environment значення шаблону у квадратних дужках.
- Закладати в кейси залежність від налаштувань адміністратора публічного demo.

## Continue (продовжувати)
- Негативні кейси та граничні значення (F-70: −1, 0, 100, 101; F-120: 0, 1, 1440, 1441) — дали багато дефектів.
- Фіксувати середовище і дату в кожному рядку журналу.
- Фіксувати дефекти негайно після виявлення.
- Дотримуватися етики demo: без навантаження, без зміни спільних паролів, лише вигадані дані.
